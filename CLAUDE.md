## Project

Arcade Vault is an online retro-arcade platform: users play browser games and compete for the highest scores. All user-facing text is in Spanish.

The repo is still the bare `create-next-app` scaffold. `app/layout.tsx` (its metadata still says "Create Next App") and `app/page.tsx` are boilerplate, and no product code exists yet.

Development follows Spec Driven Design: features are specified with `/spec` and then implemented with `/spec-impl`. Both skills come from [Klerith/fernando-skills](https://github.com/Klerith/fernando-skills), installed with `npx skills@latest add Klerith/fernando-skills`.

## Commands

```bash
npm run dev              # dev server (Turbopack) on http://localhost:3000
npm run build            # production build
npm run start            # serve the production build
npm run lint             # ESLint 9 flat config: next core-web-vitals + next typescript
npx eslint app/page.tsx  # lint a single file
npx tsc --noEmit         # type-check (route types come from .next/types; run dev/build or `npx next typegen` first)
```

No test runner or `test` script is set up yet.

## Stack and config that change how code must be written

- **Next.js 16.4 App Router, React 19.3, TypeScript strict.** Routes live in `app/`, and there is no `src/` folder. The `@/*` alias points to the repo root. Route prop types such as `LayoutProps<"/">` and `PageProps<"/route">` are global helpers generated by Next, so they need no import.
- **Tailwind CSS v4 goes through Turbopack, not PostCSS.** `next.config.ts` runs every `*.css` file through the `@tailwindcss/turbopack` loader (`turbopack.rules`). There is no `postcss.config.*`, so don't add one, even though the bundled CSS docs describe the PostCSS setup. That loader only exists under Turbopack, so a `--webpack` build would lose Tailwind. Theme tokens are CSS variables in `app/globals.css`, exposed to Tailwind with `@theme inline`.
- **`cacheComponents: true`.**
  - Data fetching is dynamic by default. Caching is opt-in, using `"use cache"` with `cacheLife`/`cacheTag`.
  - Partial Prerendering is always on. Put uncached data, and request-time APIs like `cookies()`/`headers()`, inside a `<Suspense>` boundary. Otherwise the dev overlay reports a "blocking-route" error.
  - Don't export a route-segment `runtime`.
  - On navigation, the previous route stays mounted inside React `<Activity mode="hidden">`. Its state survives back/forward, and its effects are cleaned up when it is hidden and run again when it is shown. This matters for game loops, timers and input listeners.
- **`partialPrefetching: true`** (it must stay paired with `cacheComponents`). By default, `<Link>` prefetches only the route's static App Shell. Content that depends on `params`/`searchParams` loads after navigation unless the link sets `prefetch={true}`.
- **`experimental.agentFeedback: true`.** `next dev` maintains managed blocks in `AGENTS.md` and may add a "Report Next.js feedback" block there. Commit those changes instead of deleting them.
- While `npm run dev` runs, the dev server exposes an MCP endpoint at `/_next/mcp` (`get_errors`, `get_compilation_issues`, `get_routes`, `get_logs`). The `next-devtools-mcp` package connects to it, but it is not set up in `.mcp.json` yet.

## Design reference: `resources.zip`

`resources.zip` sits untracked at the repo root and holds the UI prototype for the app in `resources/templates/`. It is a standalone `Arcade Vault.html` that runs React 18 UMD + Babel in the browser, with one JSX file per screen:

| File | Screen |
| --- | --- |
| `biblioteca.jsx` | Library: game cards, a category filter and title search |
| `detalle.jsx` | Game detail page with a per-game top-scores table and a "JUGAR AHORA" button |
| `reproductor.jsx` | Player: CRT frame, a HUD (player, score, lives, level), pause/end, a game-over modal that saves the score |
| `auth.jsx` | Sign-in / create-account tabs |
| `salon.jsx` | Salón de la Fama (global leaderboard, with podium colors) |
| `nav.jsx`, `app.jsx` | Top nav plus mobile drawer, and the screen switcher |
| `data.jsx` | Mock catalog: 8 games (`id`, `title`, `short`, `long`, `cat`, `cover`, `color`, `best`, `plays`), the `CATS` list (`TODOS/ARCADE/PUZZLE/SHOOTER/VERSUS`), and `seededScores()` for fake leaderboards |
| `styles.css` | Neon/CRT theme: color tokens (`--cyan`, `--magenta`, `--yellow`, `--green`, `--gold/silver/bronze`), fonts Press Start 2P + JetBrains Mono/Courier Prime, `av-*` classes, `cover-*` game art |

Everything behind the prototype is mocked:

- Routing is a JSON object stored in `location.hash`.
- Login accepts any input and stores `{ name }` in `localStorage.av_user`.
- Scores are appended to `localStorage.av_scores`.
- The player has no real game; the score just ticks up on a timer.

Use it as the reference for look, copy and flows, not as code to port as-is. Read a file with `unzip -p resources.zip "resources/templates/<file>"` and ignore the `__MACOSX/` entries.
